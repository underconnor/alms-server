# HTTP 계약 호환성 참고

현재 요청·응답·헤더의 기준은 [HTTP 계약](http-contract.md)과 [OpenAPI](openapi.json)다. 이 공개 저장소의 릴리스부터 계약 변경과 필요한 클라이언트 이전 방법을 함께 기록한다.

## 클라이언트가 구분해야 하는 값

- 개인 TODO·작업 목록의 `complete/hasMore/limit`는 목록 잘림을 뜻하며 개별 작업의 완료나 학교 인정을 뜻하지 않는다.
- 작업의 `executionOutcome`과 `schoolResult`는 별개다. `completed`는 재생 종료이며 학교 인정은 명시적인 근거를 확인한다.
- 학교의 제출 상태와 ALMS 제출 작업 상태, 개인 학습 완료 체크는 별개다. 미확정 작업의 학교 관찰은 원래 제출의 성공으로 귀속하지 않는다.
- 지원 상태가 없거나 nullable 값이 미제공인 경우를 실제 `false`, `0`, 빈 배열로 바꾸지 않는다.
- 파일명은 해당 응답의 안전한 `Content-Disposition`에서 읽는다. 과거 캐시의 파일명이나 서비스 fallback을 학교 원본 파일명 근거로 사용하지 않는다.
- 수동 재생의 선택적 단조 시각은 준비 응답이 지원을 광고한 경우에만 보낸다. 상세는 [수동 영상 계약](manual-video-contract.md)을 따른다.

## 변경 검사

HTTP 경로를 바꾸면 `npm run contract:generate`를 실행하고 생성된 명세와 실제 등록 경로를 대조하는 테스트를 함께 검토한다. 기존 사용자·세션·학교 generation 경계를 유지하고, 제거하거나 의미가 바뀌는 필드는 소비자 이전 절차를 설명한다.
